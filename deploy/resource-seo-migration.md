# 资料页 SEO 与 resour.nwu.icu 迁移

## 本次实现

- 全站 Vue 页面标题统一以 ` - NWU.ICU` 结尾；时间线标题为 `时间线 - NWU.ICU`。
- `/disk` 文档由 Django 输出标题、描述、canonical、面包屑、目录链接和资料信息。普通用户与爬虫使用同一文档、同一权限检查。
- 初始 HTML 的 README 以转义文本呈现，Vue 加载后按原有安全 Markdown 规则展示。嵌入的 JSON 使用 Django `json_script` 转义，Vue 首次加载复用该数据，刷新仍请求 API。
- 私有资料 HTML 禁止共享缓存、设置 noindex；匿名 sitemap 永远不包含登录用户或管理员专属资料。错误页返回 401/404/503，避免统一 SPA 200。
- `/robots.txt` 返回纯文本；`/sitemap.xml` 返回 sitemap index，分页包含公开资料目录和文件详情页。
- sitemap 复用事件更新的资源索引，并实时应用匿名访问规则；管理操作后无需定时扫描。服务器外部直接改动资料时，仍须按原流程重新建立索引。
- `/disk` 是规范根路径，子目录不带尾斜杠。文件名保留原文，不为了标题美化而改名。

## 前后端交付顺序

遵循 `production-runbook.md`、`quick-update.md`，部署已 push 的固定干净提交。本次不需要数据库迁移。

1. 部署支持 HTML 和 sitemap 的后端，再部署对应前端 gateway。
2. 前端构建在原有 hashed assets 外生成 `resource-entry.js` 和 `resource-entry.css`。它们引用同一份前端产物；gateway 对稳定入口使用 `no-cache`，hashed assets 保持长期缓存。
3. gateway 将 `/disk`、`/robots.txt`、`/sitemap.xml` 代理给 Django，保留真实状态码。后端容器不需要复制前端文件或运行 Node。
4. Windows `pnpm dev` 也代理资料文档到配置的后端；开发入口由 Vite 提供，因此本地检查应将 `VITE_BACKEND_API_URL` 指向本地后端。
5. 新站验收通过后再切换旧域名。回退时前后端使用匹配版本，先恢复静态 gateway 路由，再回退后端。

## 旧域名切换

`resour-redirect.locations.conf` 是旧域名的 location 片段，不是独立 server 配置，不会被应用发布脚本自动启用。须先发布并验收后端兼容接口，再合并到旧域名配置；不能在旧后端上提前启用。

切换前导出旧站访问日志及搜索平台主要入口 URL，核对：

- 普通详情页路径是否与新资料路径一致；改名/移动的路径添加精确映射。
- `/d/`、`/p/` 等旧直链通过兼容文件接口读取，不能将 HTML 当成文件发给下载客户端。
- 根目录是否存在恰好名为 `api`、`d`、`p`、`assets`、`static` 的真实资料目录；如有，应调整保留路径规则。
- 旧查询参数是否存在必须迁移的语义；资料页面保留普通参数并去掉旧 sign/signature/token/access/password；文件目标只保留规范 path 与预览 inline 标记，新页 canonical 不带旧查询参数。

在旧域名 HTTP/HTTPS server 中合并片段：

1. 保留现有证书、续期配置及站长平台验证文件；ACME 和验证文件的 location 必须独立保留。
2. 替换原 `location /`，检查已有正则、`^~` location 和 server 级 return/rewrite，避免绕过跳转或把 HTTP 先跳到旧站 HTTPS。
3. 精确映射直接指向最终规范新地址，不能统一跳首页。
4. 备份配置，执行实际 OpenResty 的配置检查，通过后平滑重载；不重启数据库、修改数据卷或删除旧发布。
5. 保留旧域名的访问日志、DNS、有效证书和 301，至少一年，建议长期保留。

## 验收

- 示例旧链接：恰好一次 301，Location 为对应 `https://nwu.icu/disk/...`，最终 200。
- 根目录、带尾斜杠目录、HTTP、HTTPS、查询参数都检查。
- 中文、空格、括号、`#`、`%`、`&` 文件名往返一致，没有重复编码。
- 无 JavaScript 获取新资料页时仍能读到文件名、说明、目录链接；有 JavaScript 时目录浏览、搜索、刷新、下载、预览均正常。
- 删除文件为 404；存储离线或索引缺失返回 503；私有文件不出现在匿名文档、bootstrap 或 sitemap 中。
- sitemap 每页只包含规范资料页面 URL，XML 可解析；未修改资料不人为更新 lastmod。
- 全站访问时间线、课程、登录、资料、设置与错误页，标题只有一个 ` - NWU.ICU` 后缀；跨页面切换不会保留旧资料的 canonical/noindex。
- 前端执行 `pnpm check`；后端按 `docs/testing.md` 使用唯一隔离 Compose 项目，完整测试并检查 migrations 和 Django 配置。

上线后提交新 sitemap，使用搜索平台 URL 检查确认渲染内容，记录新旧站合计搜索点击量、收录变化及重定向错误。搜索平台提交和线上 OpenResty 切换需要在实际部署阶段完成。

## 历史链接兼容实现

- 学院别名集中在 `common/file/resource_legacy_aliases.json`，包含 11 个旧名称及“物理学学院”旧拼写。随版本发布，进程启动时读取一次；修改后重新发布，不依赖数据库或后台动态配置。
- `resource_legacy.py` 仅匹配 `【3】学院课程` 下的完整学院目录段，保留其后文件路径。原始 URI 只解码一次，避免把文件名中的字面 `%23` 误转为 `#`。
- OpenResty 将 `$request_uri` 写入覆盖后的 `X-Legacy-URI`，内部代理到 `/api/resources/legacy-redirect/`。后端合并 `/local` 前缀处理、学院改名、尾斜杠规范化，只返回一次 301，目标固定为 `https://nwu.icu`。
- `/d/[local/]…` 和 `/p/[local/]…` 直接 301 到稳定的 `/api/resources/file/legacy/?path=…`，预览增加 `inline=1`。该接口复用文件接口的 ACL、真实文件解析、Range、HEAD、安全预览类型与下载统计；每次读取调用新站相同的限额/验证码授权逻辑。不会把临时签名放进永久重定向。
- 达到限额返回 429，需在新站资料页完成验证再下载；需要登录的文件仍需新站登录。旧站的 Cookie、签名不会作为授权依据。缺失文件返回 404，README 与隐藏文件不暴露，旧 `/api`、`/assets`、`/static` 返回 410。
- 兼容读取含错误响应均禁止共享缓存；用户与爬虫使用相同规则。此前“全部 d/p 返回 410”的草稿已替换。
- 配置启用仍需处理下面审计中列出的旧 location 冲突、证书和 AList 5244 旁路。这次本地修改不会自动改变现网。
