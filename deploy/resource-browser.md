# 站内资料浏览

资料页为前端 `/disk`，后端直接读取 `RESOURCE_STORAGE_ROOT`，无需 AList API。
目录与文件详情实时读取磁盘；全站资料搜索复用本地 JSON 文件树索引。

## 本机 Windows + WSL Docker

Windows 资料目录：`D:\Dropbox\nwuicu资源`。
在 WSL 中对应 `/mnt/d/Dropbox/nwuicu资源`。后端 `.env` 设置：

```dotenv
RESOURCE_STORAGE_HOST_PATH=/mnt/d/Dropbox/nwuicu资源
RESOURCE_STORAGE_ROOT=/resource-storage
```

在 WSL 中执行：

```sh
cd /mnt/e/Code/nwuicu/NWU.ICU
docker compose up -d --build
docker compose exec web python scripts/export_resource_tree.py --root /resource-storage --output /app/data/resource_directories.json
```

前端在 Windows 使用 `pnpm dev`，`.env.local` 中设置
`VITE_BACKEND_API_URL=http://127.0.0.1:8000`。不再需要 `VITE_RESOURCE_SERVICE_URL`。

## Linux 服务器

将同一台服务器上现有资料目录的**绝对路径**填入后端 `.env`，例如：

```dotenv
RESOURCE_STORAGE_HOST_PATH=/srv/nwuicu/resources
RESOURCE_STORAGE_ROOT=/resource-storage
```

示例路径必须替换为服务器实际目录，不能使用本机 `D:` 或 `/mnt/d` 路径。
Compose 将该目录挂载为容器内 `/resource-storage`，因此前后端代码无需按系统修改。
`web`、`cron` 和 `resource-worker` 必须挂载同一个资料目录；浏览接口只读，
现有投稿审批流程仍由 worker 写入该目录。目录需允许容器用户 UID 10001 读取和遍历；
需要使用投稿发布时，另外给予 worker 所需写入权限。

沿用项目的部署 Compose 文件启动，然后执行上面的索引导出命令。
现有 cron 每天更新索引；审核发布的新文件会即时合入索引。
直接从 Dropbox 或服务器文件系统增删文件后，浏览页刷新立即生效；
要立即更新全站搜索，请重新导出索引。

## 目录说明和下载

- 每个目录中的 `readme.md` 大小写不敏感，以 Markdown 渲染在文件列表上方。
- 文件详情显示所属目录说明。目录没有说明时不继承其他上级目录的说明。
- README 不出现在目录列表和搜索结果中，文件访问接口也拒绝直接读取它。
- 支持 UTF-8（含 BOM），并兼容 GB18030；说明读取上限 1 MiB，超限会显示提示。
- Markdown 支持相对链接、图片、列表与表格，解析后清理脚本及危险 HTML。
- 资料默认公开浏览、下载，无需登录；可在管理页面按目录限制为登录用户或资料管理员。
- 隐藏文件、路径越界及符号链接不公开。
- 文件夹优先，支持名称、修改时间、大小排序，以及当前目录筛选和分页。
- 文件下载流式传输，支持单段 HTTP Range、中文文件名和分享页面链接。
- PDF、常见图片和纯文本可使用浏览器预览；Office、压缩包等下载后打开。
- HTML、SVG 等可执行内容强制下载，不作为本站页面执行。

接口：`GET /api/resources/browse/?path=/目录`、
`GET /api/resources/file/?path=/目录/文件`；安全类型添加 `inline=1` 可预览。

若后续大文件并发量增加，可再配置 Nginx `X-Accel-Redirect` 接管文件传输，
保留 Django 的路径校验，减少 Gunicorn 工作进程在下载期间的占用。

## 管理文件

在 `/manage?tab=files` 的“资料管理”中操作已发布资料：

- 上传：选择目标目录，每批最多 20 个文件，单个不超过 100 MiB，上传后直接发布。
- 移动：选择文件的目标目录，保留名称和内容；不移动文件夹。
- 删除：确认后移入回收站，公开目录和搜索索引立即移除该文件。
- 恢复：在回收站选择恢复到原位置；原目录不存在或已有同名文件时拒绝覆盖。
- README 对管理员显示为“目录说明”，可上传、移动、删除和恢复；仍不作为普通文件公开。

管理员必须通过现有的 Passkey 验证，并具有独立权限
`common.manage_resource_files`（Can manage published resource files）。超级管理员默认拥有；
普通 staff 需在现有 Django Admin 中显式分配，投稿审核权限不会自动包含此权限。
更新代码后运行迁移（开发 Compose 启动会自动运行）：

```sh
docker compose exec web python manage.py migrate
```

管理操作会同步更新本地文件索引，正常情况下无需等待每日扫描。
浏览器携带文件版本，若文件在页面加载后已修改，会提示刷新并拒绝旧操作。
同名检查不区分大小写，Windows 与 Linux 均不会覆盖已有文件。
操作写入 `management.security` 日志，记录管理员、动作和资料路径。

## 维护工具与访问权限

- 文件管理支持新建文件夹、文件重命名及每批最多 100 个文件的移动/删除。批量操作逐项执行，失败时显示成功数量和失败原因，可重试未完成项。
- “目录说明”提供 Markdown 编辑和经过清理的实时预览。保存使用文件版本检查，防止旧页面覆盖其他人的更新；新文件以 UTF-8 保存，已有 README 的文件权限保持不变。
- “目录索引”显示更新时间、目录数、文件数和总大小，并可重新扫描服务器的实际目录；大目录扫描时间受磁盘速度影响。
- “操作记录”持久化保存操作人、时间、类型、原路径及目标路径，支持按操作类型、路径和操作人查询，每页 50 条。从功能启用后开始记录；服务器或 Dropbox 直接操作文件不会产生本站操作记录。
- 回收站显示总占用和删除时间，支持单个永久删除或清空。需要输入“永久删除”确认；清空只处理确认时的文件 ID 清单，之后新删除的文件保留。永久删除请求和完成分别记录，发生中断时可据此核对。
- “访问权限”可设置公开/继承上级、仅登录用户、仅资料管理员。管理员指 active staff 且拥有 `common.manage_resource_files` 权限的用户。管理写入仍要求 Passkey 验证。
- 投稿文件夹黑名单只限制投稿，不隐藏公开资料。需要禁止匿名访问时，在“资料管理”进入对应目录，通过“访问权限”设置；若需对所有普通用户隐藏，选择“仅资料管理员”。
- 上级限制自动应用到全部子目录，子目录不能放宽。规则比较不区分大小写，防止 Windows 路径别名绕过限制。浏览、搜索、直接下载、预览和普通投稿目录选择均检查相同规则。
- 此权限仅作用于本站接口。原 `resour.nwu.icu` 或其他直接暴露同一物理目录的服务需要同步设置权限，否则仍可经原服务访问。
- 权限规则保存在数据库，跟随目录路径。若从服务器外部移动/改名目录，应同步更新规则。

## 下载统计

“下载统计”提供近 7 / 30 / 90 天的总下载、游客下载、登录用户下载、每日趋势及前 50 个文件排行。同时展示独立 IP 数、登录用户数、不同 UA 数，以及 IP、用户、UA 各自的前 50 项排行。日期按后端配置的时区计算，默认 Asia/Shanghai。

统计口径为本站成功接受的附件下载请求（HTTP 200 或从字节 0 开始的 206），不表示传输完成。预览请求、HEAD、失败请求、后续分段和续传不计入。同一用户或匿名标识、同一路径在每个 5 分钟时间段内计一次；以数据库唯一键去重，支持多个服务进程。

新下载记录保存 IP 地址、User-Agent，以及登录用户的 ID 和用户名快照。用户排行按 ID 汇总，显示当前筛选范围内最近一次下载记录的用户名；账号改名或删除不改变历史归属。UA 最长保存 2048 字符，不判断浏览器身份真伪。

IP 依次读取 `X-Forwarded-For` 最左侧地址、`X-Real-IP` 和连接地址；只进行数据库所需的地址格式规范化，不设置可信 IP 或代理白名单。IPv4 与 IPv6 均支持。开发环境 Vite 会转发客户端地址，Linux Nginx 沿用现有转发头配置，无需增加环境变量。

支持按 IP 精确匹配、用户 ID、UA 关键词和文件路径关键词组合筛选，筛选同时作用于指标、趋势、排行和下载明细。明细每页 50 条，包含时间、文件、用户、IP 和 UA。历史缺失字段显示“未记录”，不回填 IP、UA 或账号；这些记录仍保留在原有下载总数中。

登录用户以用户 ID 参与去重摘要，游客以 IP 与 UA 参与带密钥的 SHA-256 摘要。一次去重时间段内 IP 与 UA 取首次计数值。共享网络可能合并匿名计数。统计失败不会阻止下载，异常写入服务日志。上述个人维度仅通过现有 Passkey 和资料管理权限门禁后的管理接口返回。

只统计功能启用后的本站下载，不回填原站历史记录。文件移动/改名后，原下载记录保留当时路径。统计、操作记录和访问权限需要备份数据库；文件和回收站仍备份物理目录。

数据库迁移为 `0043_resource_management_tools` 和 `0044_resource_download_dimensions`。升级前先完成迁移，再启动新后端代码（本项目开发 Compose 启动时自动迁移）。

回收站和上传临时文件保存在资料根目录下 `.nwuicu-management/`，不公开也不进入目录索引。
回收站不会自动清空，保留恢复能力也会继续占用磁盘；备份时保留该目录中的 `.json` 与 `.data` 配对文件。
文件发布和移动通过同一文件系统中的硬链接避免覆盖，支持 NTFS 和 Linux 文件系统。
目录跨挂载点或文件系统不支持硬链接时会拒绝操作并保留原文件。
服务用户 UID 10001 需要写入资料目录和索引目录；不要把资料管理挂载改成只读。
